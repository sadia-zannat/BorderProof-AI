# Five-stage incremental delivery agreement

- **V1 — Foundation:** this source archive; actual Python/API/browser fallback tests. Main Next npm build unverified because npm network unavailable.
- **V2 — Financial agent:** safe document extraction, provider-agnostic grounded information, missing-field dialogue, versioned reference/quote, *real internal sandbox ledger*, receipt and logs. Externally credentialed sandbox adapter only when granted.
- **V3 — Security BPCE:** independent financial safety kernel, evidence binding, versioned authorization, replay/expiry/change invalidation, cross-tenant tests, concurrency and state-machine invariants, threat matrix.
- **V4 — Research:** genuine labeled StuPay-IntegrityBench, baseline implementations, ablations, attack traces, measured outcomes, more advanced graph interactions and localization/accessibility verification.
- **V5 — Final:** full regression and UI review, real measured evidence, submission slide deck, security self-assessment, paper/novelty matrix, demo script/video guidance, versioned archive, Work-mode audit handoff.

Each `next` must start from the full preceding source ZIP and deliver a complete new ZIP. Failed or unverified modules must remain visibly marked rather than being declared complete. A `next` never approves payment, external actions, registration or organizer submission.
